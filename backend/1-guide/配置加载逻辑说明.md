# 配置加载逻辑说明

## 核心逻辑

配置加载由 `app/core/config.py` 中的 `get_env_files()` 函数控制。

## 配置文件位置

配置文件位于 **`api` 目录**（backend 的父目录）：
- `/root/finance/api/.env` - 基础配置
- `/root/finance/api/.env.{profile}` - Profile 特定配置

**注意**：不是 `backend` 目录，而是 `api` 目录！

## 加载规则

### 情况1：未设置 ENV_PROFILE（当前服务器状态）

```python
# 如果没有设置 ENV_PROFILE
if not profile:
    return []  # 不加载任何 .env 文件
```

**行为**：
- ✅ 不加载任何 `.env` 文件
- ✅ 使用代码中的默认值（测试环境配置）
- ✅ 数据库配置：`POSTGRES_PASSWORD=Pg2025Secure`
- ✅ `SECRET_KEY`：使用代码默认值（不是 `.env` 中的 `changethis`）

**适用场景**：测试分支，不依赖服务器配置文件

### 情况2：设置了 ENV_PROFILE

```python
# 如果设置了 ENV_PROFILE=staging
# 1. 先加载基础配置
env_files.append("/root/finance/api/.env")

# 2. 再加载 profile 配置（会覆盖基础配置）
env_files.append("/root/finance/api/.env.staging")
```

**行为**：
- ✅ 先加载 `.env`（基础配置）
- ✅ 再加载 `.env.{profile}`（覆盖基础配置）
- ⚠️ `.env` 中的 `SECRET_KEY=changethis` 会被读取
- ⚠️ 如果 `.env.staging` 中没有数据库配置，会使用 `.env` 中的配置

## 当前服务器问题分析

### 问题1：数据库连接失败

**错误信息**：
```
FATAL: password authentication failed for user "postgres"
```

**原因**：
- 代码默认密码：`Pg2025Secure`
- 实际数据库密码可能不同

**解决方案**：
1. **方案A**：修改数据库密码为 `Pg2025Secure`
2. **方案B**：创建 `.env.staging` 文件，设置正确的密码
3. **方案C**：在 systemd 服务中设置 `ENV_PROFILE=staging`，并创建 `.env.staging`

### 问题2：.env 文件位置

当前 `.env` 文件在 `/root/finance/api/.env`，这是**正确的位置**。

### 问题3：ENV_PROFILE 未设置

从日志看，没有设置 `ENV_PROFILE`，所以：
- ✅ 使用代码默认值
- ✅ 数据库密码应该是 `Pg2025Secure`
- ❌ 但数据库实际密码可能不是这个

## 推荐解决方案

### 方案1：不设置 ENV_PROFILE，修改数据库密码（最简单）

```bash
# 在服务器上执行
sudo -u postgres psql

# 修改密码
ALTER USER postgres WITH PASSWORD 'Pg2025Secure';

# 退出
\q

# 重启 API 服务
systemctl restart finance-api.service
```

### 方案2：设置 ENV_PROFILE，创建 .env.staging（推荐）

**步骤1**：创建 `.env.staging` 文件

```bash
cat > /root/finance/api/.env.staging << 'EOF'
# 测试环境配置
ENV_PROFILE=staging

# 数据库配置
POSTGRES_SERVER=192.168.31.150
POSTGRES_PORT=5432
POSTGRES_USER=postgres
POSTGRES_PASSWORD=Pg2025Secure  # 或实际密码
POSTGRES_DB=finance

# 环境配置
ENVIRONMENT=staging
FRONTEND_HOST=http://192.168.31.150
BACKEND_CORS_ORIGINS=http://192.168.31.150,http://localhost:5173

# 安全配置
SECRET_KEY=KaC9MXDkiiBZohHHlS7ZEU5BDHvJeZwAhPwDW5QLZhs

# 超级用户配置
FIRST_SUPERUSER=admin@hangrong.com
FIRST_SUPERUSER_PASSWORD=Admin@2025Secure
EOF
```

**步骤2**：修改 systemd 服务，设置 ENV_PROFILE

```bash
sudo nano /etc/systemd/system/finance-api.service
```

在 `[Service]` 部分添加：
```ini
[Service]
...
Environment="ENV_PROFILE=staging"
```

**步骤3**：重新加载并重启服务

```bash
sudo systemctl daemon-reload
sudo systemctl restart finance-api.service
sudo systemctl status finance-api.service
```

## 配置优先级总结

1. **环境变量**（最高优先级）
2. **`.env.{profile}`** 文件（如果设置了 ENV_PROFILE）
3. **`.env`** 文件（如果设置了 ENV_PROFILE）
4. **代码默认值**（如果未设置 ENV_PROFILE）

## 验证配置

### 检查当前使用的配置

```bash

journalctl -u finance-api.service -n 100 | grep -E "Config|POSTGRES|ENV_PROFILE"
```

### 测试数据库连接

```bash
# 使用代码默认密码
PGPASSWORD=Pg2025Secure psql -h 192.168.31.150 -U postgres -d finance -c "SELECT 1;"
```

### 检查环境变量

```bash
# 查看 systemd 服务环境变量
systemctl show finance-api.service | grep Environment

# 查看运行进程的环境变量
cat /proc/$(pgrep -f "uvicorn app.main:app" | head -1)/environ | tr '\0' '\n' | grep ENV_PROFILE
```

## 常见问题

### Q1: 为什么修改了 .env 文件，配置没有生效？

**A**: 检查是否设置了 `ENV_PROFILE`：
- 如果未设置，不会加载 `.env` 文件
- 如果设置了，需要重启服务

### Q2: 配置文件应该放在哪里？

**A**: 放在 `api` 目录（backend 的父目录）：
- ✅ `/root/finance/api/.env`
- ✅ `/root/finance/api/.env.staging`
- ❌ `/root/finance/api/backend/.env`（错误位置）

### Q3: 如何确认当前使用的配置？

**A**: 查看服务日志：
```bash
journalctl -u finance-api.service -n 50 | grep -E "Config|POSTGRES"
```

### Q4: 数据库密码在哪里配置？

**A**: 
- 如果未设置 `ENV_PROFILE`：使用代码默认值 `Pg2025Secure`
- 如果设置了 `ENV_PROFILE`：在 `.env.{profile}` 文件中配置
