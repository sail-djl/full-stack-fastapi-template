# 完整初始化启动链路

## 概述

本文档详细说明 FastAPI 后端应用的完整初始化启动链路，从 Docker Compose 启动到应用完全就绪的每个步骤。

## 启动方式

### 方式一：Docker Compose（生产/开发环境）

使用 Docker Compose 启动整个应用栈，包括数据库、后端、前端等服务。

### 方式二：本地开发（不使用 Docker）

直接在本地环境运行，需要手动启动数据库和配置环境。

---

## Docker Compose 启动链路

### 阶段 1：Docker Compose 初始化

**触发命令：**
```bash
docker compose up -d
```

**执行内容：**
1. 读取 `docker-compose.yml` 配置
2. 读取 `.env` 环境变量文件
3. 构建 Docker 镜像（如果不存在）
4. 创建 Docker 网络和卷
5. 按依赖顺序启动服务

**服务依赖关系：**
```
db (PostgreSQL)
  ↓
prestart (初始化脚本)
  ↓
backend (FastAPI 应用)
```

---

### 阶段 2：数据库服务启动（db）

**服务配置：** `docker-compose.yml`

```yaml
db:
  image: postgres:17
  restart: always
  healthcheck:
    test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
    interval: 10s
    retries: 5
    start_period: 30s
```

**执行步骤：**

1. **启动 PostgreSQL 容器**
   - 从 `postgres:17` 镜像创建容器
   - 挂载数据卷：`app-db-data`

2. **初始化数据库**
   - 读取环境变量：`POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`
   - 创建数据库和用户
   - 设置数据目录：`/var/lib/postgresql/data/pgdata`

3. **健康检查**
   - 每 10 秒检查一次数据库是否就绪
   - 使用 `pg_isready` 命令
   - 最多重试 5 次
   - 启动等待期 30 秒

4. **等待就绪**
   - 数据库健康检查通过后，标记为 `healthy`
   - 其他服务可以开始启动

**关键文件：**
- `docker-compose.yml` - 服务配置
- `.env` - 数据库连接配置

---

### 阶段 3：初始化脚本执行（prestart）

**服务配置：** `docker-compose.yml`

```yaml
prestart:
  image: '${DOCKER_IMAGE_BACKEND}:${TAG-latest}'
  depends_on:
    db:
      condition: service_healthy
  command: bash scripts/prestart.sh
```

**执行条件：**
- ✅ 数据库服务健康检查通过（`service_healthy`）
- ✅ 后端镜像已构建

**执行脚本：** `scripts/prestart.sh`

#### 步骤 3.1：等待数据库就绪

**脚本：** `app/backend_pre_start.py`

```python
@retry(
    stop=stop_after_attempt(300),  # 最多尝试 300 次
    wait=wait_fixed(1),  # 每次等待 1 秒
)
def init(db_engine: Engine) -> None:
    with Session(db_engine) as session:
        session.exec(select(1))  # 测试数据库连接
```

**功能：**
- 检查数据库连接是否可用
- 使用重试机制，最多等待 5 分钟
- 执行简单的 `SELECT 1` 查询测试连接

**执行流程：**
```
尝试连接 → 失败 → 等待 1 秒 → 重试
         ↓
       成功 → 继续下一步
```

**关键文件：**
- `app/backend_pre_start.py` - 数据库连接检查
- `app/core/db.py` - 数据库引擎

#### 步骤 3.2：执行数据库迁移

**命令：**
```bash
alembic upgrade head
```

**功能：**
- 读取 Alembic 迁移文件
- 检查当前数据库版本
- 执行所有未应用的迁移
- 创建/更新数据库表结构

**迁移文件位置：**
- `app/alembic/versions/` - 迁移脚本目录
- `alembic.ini` - Alembic 配置文件

**执行内容：**
1. 连接数据库
2. 查询 `alembic_version` 表获取当前版本
3. 按顺序执行迁移脚本的 `upgrade()` 函数
4. 更新数据库版本号

**关键文件：**
- `alembic.ini` - Alembic 配置
- `app/alembic/env.py` - Alembic 环境配置
- `app/alembic/versions/*.py` - 迁移脚本

#### 步骤 3.3：创建初始数据

**脚本：** `app/initial_data.py`

```python
def init() -> None:
    with Session(engine) as session:
        init_db(session)
```

**功能：**
- 创建初始超级用户（如果不存在）
- 从配置读取：`FIRST_SUPERUSER`, `FIRST_SUPERUSER_PASSWORD`

**执行逻辑：** `app/core/db.py`

```python
def init_db(session: Session) -> None:
    # 检查用户是否存在
    user = session.exec(
        select(User).where(User.email == settings.FIRST_SUPERUSER)
    ).first()
    
    # 如果不存在，创建用户
    if not user:
        user_in = UserCreate(
            email=settings.FIRST_SUPERUSER,
            password=settings.FIRST_SUPERUSER_PASSWORD,
            is_superuser=True,
        )
        user = crud.create_user(session=session, user_create=user_in)
```

**密码处理：**
- 密码通过 `crud.create_user()` 自动加密（Bcrypt）
- 使用 `app/core/security.py` 中的 `get_password_hash()`

**关键文件：**
- `app/initial_data.py` - 初始数据脚本
- `app/core/db.py` - 初始化函数
- `app/crud.py` - 用户创建逻辑
- `app/core/security.py` - 密码加密

**prestart 完成标志：**
- 脚本执行成功，退出码为 0
- `backend` 服务可以开始启动

---

### 阶段 4：FastAPI 应用启动（backend）

**服务配置：** `docker-compose.yml`

```yaml
backend:
  depends_on:
    db:
      condition: service_healthy
    prestart:
      condition: service_completed_successfully
  command: fastapi run --workers 4 app/main.py
```

**执行条件：**
- ✅ 数据库服务健康
- ✅ prestart 服务成功完成

**启动命令：**
```bash
fastapi run --workers 4 app/main.py
```

**参数说明：**
- `--workers 4`: 启动 4 个工作进程（生产环境）
- `app/main.py`: 应用入口文件

#### 步骤 4.1：Python 模块加载

**执行顺序：**

1. **加载标准库和第三方库**
   - `fastapi`, `sqlmodel`, `pydantic` 等

2. **加载应用模块**
   - `app.core.config` - 配置模块
   - `app.core.db` - 数据库模块
   - `app.core.security` - 安全模块
   - `app.models` - 数据模型
   - `app.api` - API 路由

#### 步骤 4.2：配置加载（app/core/config.py）

**执行内容：**

```python
# 1. 读取环境变量
settings = Settings()

# 2. 加载 .env 文件
env_file="../.env"

# 3. 验证配置
@model_validator(mode="after")
def _enforce_non_default_secrets(self) -> Self:
    # 检查默认值，生产环境强制修改
    ...
```

**配置项：**
- API 配置：`API_V1_STR`, `PROJECT_NAME`
- 安全配置：`SECRET_KEY`, `ACCESS_TOKEN_EXPIRE_MINUTES`
- 数据库配置：`POSTGRES_*`
- CORS 配置：`BACKEND_CORS_ORIGINS`, `FRONTEND_HOST`
- 邮件配置：`SMTP_*`
- 用户配置：`FIRST_SUPERUSER`, `FIRST_SUPERUSER_PASSWORD`

**计算字段：**
- `SQLALCHEMY_DATABASE_URI` - 数据库连接 URI
- `all_cors_origins` - CORS 允许的源列表
- `emails_enabled` - 邮件功能是否启用

#### 步骤 4.3：数据库引擎创建（app/core/db.py）

**执行内容：**

```python
engine = create_engine(str(settings.SQLALCHEMY_DATABASE_URI))
```

**功能：**
- 创建 SQLModel 数据库引擎
- 连接字符串从 `settings.SQLALCHEMY_DATABASE_URI` 获取
- 全局单例，整个应用共享

#### 步骤 4.4：FastAPI 应用初始化（app/main.py）

**执行内容：**

```python
# 1. 初始化 Sentry（可选）
if settings.SENTRY_DSN and settings.ENVIRONMENT != "local":
    sentry_sdk.init(dsn=str(settings.SENTRY_DSN), enable_tracing=True)

# 2. 创建 FastAPI 应用
app = FastAPI(
    title=settings.PROJECT_NAME,
    openapi_url=f"{settings.API_V1_STR}/openapi.json",
    generate_unique_id_function=custom_generate_unique_id,
)

# 3. 配置 CORS 中间件
if settings.all_cors_origins:
    app.add_middleware(
        CORSMiddleware,
        allow_origins=settings.all_cors_origins,
        allow_credentials=True,
        allow_methods=["*"],
        allow_headers=["*"],
    )

# 4. 注册 API 路由
app.include_router(api_router, prefix=settings.API_V1_STR)
```

**功能：**
- 创建 FastAPI 应用实例
- 配置 OpenAPI 文档路径
- 添加 CORS 中间件（如果配置了）
- 注册所有 API 路由

#### 步骤 4.5：API 路由注册（app/api/main.py）

**执行内容：**

```python
api_router = APIRouter()

# 注册子路由
api_router.include_router(login.router)   # 登录路由
api_router.include_router(users.router)   # 用户路由
api_router.include_router(utils.router)   # 工具路由
api_router.include_router(items.router)   # 物品路由

# 本地环境添加私有路由
if settings.ENVIRONMENT == "local":
    api_router.include_router(private.router)
```

**路由前缀：**
- 所有路由使用 `/api/v1` 前缀
- 例如：`/api/v1/login/access-token`

#### 步骤 4.6：启动 HTTP 服务器

**执行内容：**

```bash
fastapi run --workers 4 app/main.py
```

**功能：**
- 启动 Uvicorn 服务器
- 监听端口：8000（默认）
- 工作进程数：4（生产环境）
- 加载 `app.main:app` 应用实例

**服务器就绪标志：**
- 健康检查通过：`/api/v1/utils/health-check/`
- 可以接受 HTTP 请求

## 本地开发启动链路

### 前置条件

1. **安装依赖**
   ```bash
   cd backend
   uv sync
   source .venv/bin/activate
   ```

   ```bash

```

## 故障排查

### 问题 1：数据库连接失败

**症状：** `backend_pre_start.py` 一直重试

**可能原因：**
- 数据库服务未启动
- 数据库配置错误
- 网络问题

**解决方案：**
1. 检查数据库服务状态：`docker compose ps db`
2. 验证 `.env` 文件中的数据库配置
3. 检查数据库日志：`docker compose logs db`

### 问题 2：迁移执行失败

**症状：** `alembic upgrade head` 报错

**可能原因：**
- 迁移文件有错误
- 数据库状态不一致
- 权限问题

**解决方案：**
1. 查看迁移历史：`alembic history`
2. 检查当前版本：`alembic current`
3. 手动修复数据库或回滚迁移

### 问题 3：初始用户创建失败

**症状：** `initial_data.py` 执行失败

**可能原因：**
- 表结构不存在
- 配置错误
- 用户已存在但密码错误

**解决方案：**
1. 确保迁移已成功执行
2. 检查 `FIRST_SUPERUSER` 和 `FIRST_SUPERUSER_PASSWORD` 配置
3. 查看应用日志

### 问题 4：应用启动失败

**症状：** FastAPI 应用无法启动

**可能原因：**
- 配置错误
- 模块导入错误
- 端口被占用

**解决方案：**
1. 检查配置验证错误
2. 查看 Python 错误日志
3. 检查端口占用：`lsof -i :8000`

## 总结

完整的初始化启动链路包括：

1. **数据库服务启动** - PostgreSQL 容器启动并健康检查
2. **初始化脚本执行** - 等待数据库、执行迁移、创建初始数据
3. **FastAPI 应用启动** - 加载配置、初始化应用、注册路由、启动服务器

整个过程是自动化的，通过 Docker Compose 的依赖关系确保正确的执行顺序。每个步骤都有相应的错误处理和日志记录，便于故障排查。
