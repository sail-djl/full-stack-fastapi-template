# 本地开发 - 新建数据库完整指南

## 概述

本文档详细说明如何在本地开发环境中新建和配置 PostgreSQL 数据库，不使用 Docker，直接在本地安装和运行 PostgreSQL。

## 步骤 1：安装 PostgreSQL

### Windows 安装方式

#### 方式 1：使用安装包（推荐）

1. **访问 PostgreSQL 官网**
   - 网址：https://www.postgresql.org/download/windows/
   - 下载 PostgreSQL 17 安装程序

2. **运行安装程序**
   - 选择安装路径（默认：`C:\Program Files\PostgreSQL\17`）
   - **重要**：记住安装时设置的 `postgres` 用户密码
   - 选择端口（默认：5432）
   - 选择区域设置（默认：Chinese, China）

3. **完成安装**
   - 安装完成后，PostgreSQL 服务会自动启动
   - 可以选择安装 pgAdmin（图形化管理工具）

#### 方式 2：使用 Chocolatey

```powershell
# 安装 Chocolatey（如果未安装）
# 然后运行：
choco install postgresql

# 启动服务
Start-Service postgresql-x64-17
```

#### 方式 3：使用 Docker（仅数据库）

如果不想安装完整的 PostgreSQL，可以使用 Docker 只运行数据库：

```powershell
# 在项目根目录执行
cd E:\finance\full-stack-fastapi-template

# 只启动数据库服务
docker compose up db -d

# 查看日志
docker compose logs db
```

### 验证安装

```powershell
# 检查 PostgreSQL 服务是否运行
Get-Service postgresql*

# 或检查端口是否监听
netstat -an | findstr 5432

# 测试连接
psql -U postgres -c "SELECT version();"
```

**预期输出：**
```
PostgreSQL 17.x on x86_64-pc-windows...
```

## 步骤 2：创建数据库

### 方法 1：使用 psql 命令行（推荐）

#### 连接到 PostgreSQL

```powershell
# 使用默认 postgres 用户连接
psql -U postgres

# 如果提示输入密码，输入安装时设置的密码
```

#### 在 psql 中执行 SQL

```sql
-- 创建数据库
CREATE DATABASE app;

-- 验证数据库是否创建成功
\l

-- 查看所有数据库（应该能看到 app 数据库）
-- 退出 psql
\q
```

#### 完整示例

```powershell
# 方式 1：交互式
psql -U postgres
# 然后输入密码，执行 CREATE DATABASE app;

# 方式 2：命令行直接执行
psql -U postgres -c "CREATE DATABASE app;"
```

### 方法 2：使用 SQL 脚本

创建文件 `create_db.sql`：

```sql
-- 创建数据库
CREATE DATABASE app;

-- 创建专用用户（可选，推荐用于生产环境）
CREATE USER app_user WITH PASSWORD 'your_secure_password';
GRANT ALL PRIVILEGES ON DATABASE app TO app_user;

-- 连接到新数据库并设置权限
\c app
GRANT ALL PRIVILEGES ON SCHEMA public TO app_user;
```

执行脚本：

```powershell
psql -U postgres -f create_db.sql
```

### 方法 3：使用图形化工具

#### pgAdmin

1. **打开 pgAdmin**
   - 如果安装时选择了 pgAdmin，从开始菜单启动

2. **连接到服务器**
   - 右键 "Servers" → "Create" → "Server"
   - General 标签：输入名称（如 "Local PostgreSQL"）
   - Connection 标签：
     - Host: `localhost`
     - Port: `5432`
     - Database: `postgres`
     - Username: `postgres`
     - Password: 安装时设置的密码

3. **创建数据库**
   - 展开服务器 → 右键 "Databases" → "Create" → "Database"
   - Database: `app`
   - Owner: `postgres`
   - 点击 "Save"

#### DBeaver

1. **下载安装 DBeaver**
   - 网址：https://dbeaver.io/

2. **创建连接**
   - 新建连接 → 选择 PostgreSQL
   - 配置连接信息：
     - Host: `localhost`
     - Port: `5432`
     - Database: `postgres`
     - Username: `postgres`
     - Password: 安装时设置的密码

3. **创建数据库**
   - 连接到服务器后
   - 右键 "Databases" → "Create New Database"
   - 输入名称：`app`
   - 点击 "OK"

## 步骤 3：配置环境变量

### 创建 .env 文件

在项目根目录（`E:\finance\full-stack-fastapi-template`）创建或编辑 `.env` 文件：

```env
# ============================================
# 项目配置
# ============================================
PROJECT_NAME=FastAPI Project

# ============================================
# API 配置
# ============================================
API_V1_STR=/api/v1

# ============================================
# 安全配置
# ============================================
# 生成密钥命令: python -c "import secrets; print(secrets.token_urlsafe(32))"
SECRET_KEY=your-secret-key-here
ACCESS_TOKEN_EXPIRE_MINUTES=11520  # 8 天

# ============================================
# 环境配置
# ============================================
ENVIRONMENT=local
FRONTEND_HOST=http://localhost:5173

# ============================================
# 数据库配置（本地开发）
# ============================================
POSTGRES_SERVER=localhost          # 本地开发使用 localhost（不是 db）
POSTGRES_PORT=5432
POSTGRES_USER=postgres             # 或你创建的用户名
POSTGRES_PASSWORD=your_password    # 安装时设置的密码
POSTGRES_DB=app                    # 刚创建的数据库名

# ============================================
# CORS 配置
# ============================================
BACKEND_CORS_ORIGINS=http://localhost:3000,http://localhost:8080,http://localhost:5173

# ============================================
# 初始用户配置
# ============================================
FIRST_SUPERUSER=admin@example.com
FIRST_SUPERUSER_PASSWORD=changethis  # 生产环境必须修改

# ============================================
# 邮件配置（可选，本地开发可以不配置）
# ============================================
SMTP_TLS=True
SMTP_PORT=587
SMTP_HOST=
SMTP_USER=
SMTP_PASSWORD=
EMAILS_FROM_EMAIL=
EMAILS_FROM_NAME=

# ============================================
# Sentry 配置（可选）
# ============================================
SENTRY_DSN=
```

### 重要配置说明

#### 数据库配置

```env
POSTGRES_SERVER=localhost    # ⚠️ 本地开发必须是 localhost，不是 db
POSTGRES_PORT=5432           # 默认端口
POSTGRES_USER=postgres       # 默认超级用户
POSTGRES_PASSWORD=xxx        # 安装时设置的密码
POSTGRES_DB=app              # 刚创建的数据库名
```

**注意：**
- `POSTGRES_SERVER` 在本地开发时必须是 `localhost` 或 `127.0.0.1`
- Docker 环境中使用 `db`（服务名），本地开发使用 `localhost`

#### 生成 SECRET_KEY

```powershell
# 使用 Python 生成安全的密钥
python -c "import secrets; print(secrets.token_urlsafe(32))"

# 或使用 uv
uv run python -c "import secrets; print(secrets.token_urlsafe(32))"
```

将生成的密钥复制到 `.env` 文件的 `SECRET_KEY` 中。

## 步骤 5：执行初始化流程

### 5.1 等待数据库就绪

```powershell
# 确保在 backend 目录
cd E:\finance\full-stack-fastapi-template\backend

# 执行数据库连接检查
uv run python app/backend_pre_start.py
```

**预期输出：**
```
INFO:app.backend_pre_start:Initializing service
INFO:app.backend_pre_start:Service finished initializing
```

**如果失败：**
- 检查 PostgreSQL 服务是否运行
- 检查 `.env` 文件中的数据库配置
- 检查数据库 `app` 是否已创建

### 5.2 执行数据库迁移

```powershell
# 执行 Alembic 迁移，创建数据库表结构
uv run alembic upgrade head
```

**预期输出：**
```
INFO  [alembic.runtime.migration] Context impl PostgresqlImpl.
INFO  [alembic.runtime.migration] Will assume transactional DDL.
INFO  [alembic.runtime.migration] Running upgrade  -> e2412789c190, Initialize models
INFO  [alembic.runtime.migration] Running upgrade e2412789c190 -> d98dd8ec85a3, edit replace id integers in all models
...
INFO  [alembic.runtime.migration] Running upgrade 9c0a54914c78 -> 1a31ce608336, add cascade delete relationships
```

**这会创建：**
- `user` 表（用户表）
- `item` 表（物品表）
- `alembic_version` 表（迁移版本表）
- 相关索引和外键约束

### 5.3 创建初始数据

```powershell
# 创建初始超级用户
uv run python app/initial_data.py
```

**预期输出：**
```
INFO:app.initial_data:Creating initial data
INFO:app.initial_data:Initial data created
```

**这会创建：**
- 初始超级用户（邮箱和密码来自 `.env` 文件）
- 密码会自动使用 Bcrypt 加密存储

## 步骤 6：验证数据库

### 使用 psql 查看

```powershell
# 连接到 app 数据库
psql -U postgres -d app

# 查看所有表
\dt

# 查看表结构
\d user
\d item

# 查看用户数据
SELECT id, email, is_superuser, is_active, full_name FROM "user";

# 查看表数量
SELECT COUNT(*) FROM "user";

# 退出
\q
```

**预期输出：**
```
          List of relations
 Schema |     Name      | Type  |  Owner
--------+---------------+-------+----------
 public | alembic_version | table | postgres
 public | item          | table | postgres
 public | user          | table | postgres

(3 rows)
```

### 使用 Python 验证

```powershell
# 验证数据库连接和表
uv run python -c "
from app.core.db import engine
from sqlmodel import Session, select, text
from app.models import User

with Session(engine) as session:
    # 检查表是否存在
    result = session.exec(text(\"SELECT COUNT(*) FROM information_schema.tables WHERE table_schema = 'public'\"))
    table_count = result.first()
    print(f'✅ 表数量: {table_count}')
    
    # 检查用户数据
    users = session.exec(select(User)).all()
    print(f'✅ 用户数量: {len(users)}')
    if users:
        print(f'✅ 初始用户: {users[0].email}')
"
```

## 常见问题排查

### 问题 1：psql 命令找不到

**症状：**
```
psql : 无法将"psql"项识别为 cmdlet、函数、脚本文件或可运行程序的名称
```

**解决方案：**

1. **找到 PostgreSQL 安装路径**
   - 默认：`C:\Program Files\PostgreSQL\17\bin`
   - 或搜索 `psql.exe`

2. **添加到 PATH 环境变量**
   ```powershell
   # 临时添加到当前会话
   $env:PATH += ";C:\Program Files\PostgreSQL\17\bin"
   
   # 永久添加（需要管理员权限）
   [Environment]::SetEnvironmentVariable("Path", $env:Path + ";C:\Program Files\PostgreSQL\17\bin", "User")
   ```

3. **或使用完整路径**
   ```powershell
   & "C:\Program Files\PostgreSQL\17\bin\psql.exe" -U postgres
   ```

### 问题 2：连接被拒绝

**症状：**
```
psql: error: connection to server at "localhost" (::1), port 5432 failed
```

**解决方案：**

1. **检查服务是否运行**
   ```powershell
   Get-Service postgresql*
   # 如果未运行，启动服务
   Start-Service postgresql-x64-17
   ```

2. **检查端口是否监听**
   ```powershell
   netstat -an | findstr 5432
   # 应该看到: 0.0.0.0:5432 或 [::]:5432
   ```

3. **检查防火墙**
   - Windows 防火墙可能阻止了 PostgreSQL
   - 允许 PostgreSQL 通过防火墙

4. **检查配置文件**
   - 确认 `postgresql.conf` 中 `listen_addresses = '*'`
   - 确认 `pg_hba.conf` 允许本地连接

### 问题 3：密码错误

**症状：**
```
psql: error: password authentication failed for user "postgres"
```

**解决方案：**

1. **确认密码**
   - 检查安装时设置的密码
   - 或使用 Windows 认证（如果配置了）

2. **重置密码**
   ```powershell
   # 使用 Windows 认证登录（如果配置了）
   psql -U postgres
   
   # 在 psql 中重置密码
   ALTER USER postgres WITH PASSWORD 'new_password';
   ```

3. **检查 .env 文件**
   - 确认 `POSTGRES_PASSWORD` 与数据库密码一致

### 问题 4：数据库不存在

**症状：**
```
psql: error: FATAL:  database "app" does not exist
```

**解决方案：**

1. **确认数据库已创建**
   ```powershell
   psql -U postgres -c "\l"
   # 查看是否列出 app 数据库
   ```

2. **如果不存在，创建数据库**
   ```powershell
   psql -U postgres -c "CREATE DATABASE app;"
   ```

3. **检查 .env 文件**
   - 确认 `POSTGRES_DB=app` 与创建的数据库名一致

### 问题 5：迁移执行失败

**症状：**
```
alembic.util.exc.CommandError: Target database is not up to date
```

**解决方案：**

1. **查看当前版本**
   ```powershell
   uv run alembic current
   ```

2. **查看迁移历史**
   ```powershell
   uv run alembic history
   ```

3. **强制升级到最新版本**
   ```powershell
   uv run alembic upgrade head
   ```

4. **如果数据库状态混乱，可以重置**
   ```powershell
   # ⚠️ 警告：这会删除所有数据
   psql -U postgres -d app -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"
   uv run alembic upgrade head
   ```

### 问题 6：初始用户创建失败

**症状：**
```
ERROR: relation "user" does not exist
```

**解决方案：**

1. **确保迁移已执行**
   ```powershell
   uv run alembic upgrade head
   ```

2. **检查表是否存在**
   ```powershell
   psql -U postgres -d app -c "\dt"
   ```

3. **手动检查配置**
   - 确认 `.env` 中的 `FIRST_SUPERUSER` 和 `FIRST_SUPERUSER_PASSWORD` 已配置

## 本地开发 vs Docker 开发对比

| 特性 | 本地开发 | Docker 开发 |
|------|---------|------------|
| **数据库安装** | 需要本地安装 PostgreSQL | Docker 自动管理 |
| **配置** | `POSTGRES_SERVER=localhost` | `POSTGRES_SERVER=db` |
| **数据持久化** | 本地文件系统 | Docker 卷 |
| **启动速度** | 快（服务已运行） | 较慢（需要启动容器） |
| **资源占用** | 持续占用 | 可随时停止 |
| **适用场景** | 长期开发 | 快速测试、CI/CD |
