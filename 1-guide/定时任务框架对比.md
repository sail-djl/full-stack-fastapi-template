## 详细框架介绍

### 1. APScheduler ⭐⭐⭐⭐⭐ (最推荐)

#### 特点

**优点：**
- ✅ **轻量级**：无需额外的消息队列或中间件（如 Redis/RabbitMQ）
- ✅ **易于集成**：可直接在 FastAPI 应用内运行
- ✅ **功能完整**：支持 Cron、间隔、一次性等多种触发器
- ✅ **异步支持**：支持 `AsyncIOScheduler`
- ✅ **持久化可选**：支持数据库持久化（SQLite/PostgreSQL）
- ✅ **API 友好**：易于通过 FastAPI 路由动态管理任务

**缺点：**
- ❌ 不支持分布式（单机运行）
- ❌ 不适合大量任务（建议 < 1000 个任务）
- ❌ 重启后内存中的任务会丢失（除非使用持久化）

#### 适用场景

- ✅ 中小型应用（单机部署）
- ✅ 简单定时任务（数据同步、报表生成、清理等）
- ✅ 需要快速集成到现有 FastAPI 应用
- ✅ 任务数量较少（< 100 个）
- ✅ 不需要分布式任务调度

#### 代码示例

```python
from apscheduler.schedulers.asyncio import AsyncIOScheduler
from apscheduler.triggers.cron import CronTrigger

scheduler = AsyncIOScheduler()

# 每天凌晨2点执行
scheduler.add_job(
    daily_task,
    CronTrigger(hour=2, minute=0),
    id='daily_task'
)

# 每5分钟执行
scheduler.add_job(
    interval_task,
    'interval',
    minutes=5,
    id='interval_task'
)

scheduler.start()
```

### 2. Celery ⭐⭐⭐⭐ (大型应用推荐)

#### 特点

**优点：**
- ✅ **功能强大**：完整的任务队列系统
- ✅ **分布式**：支持多 Worker 分布式执行
- ✅ **持久化**：任务持久化到 Redis/RabbitMQ
- ✅ **可扩展**：支持大量任务和并发
- ✅ **生态丰富**：有 Flower（监控）、Celery Beat（定时任务）
- ✅ **重试机制**：内置任务重试和错误处理

**缺点：**
- ❌ **复杂度高**：需要额外的消息队列（Redis/RabbitMQ）
- ❌ **学习曲线陡峭**：配置和使用相对复杂
- ❌ **资源消耗**：需要额外的中间件服务
- ❌ **过度设计**：简单任务可能过于复杂

#### 适用场景

- ✅ 大型应用（多服务器部署）
- ✅ 需要分布式任务执行
- ✅ 任务数量多（> 1000 个）
- ✅ 需要任务优先级、工作流等高级功能
- ✅ 已有 Redis/RabbitMQ 基础设施

#### 架构示例

```
FastAPI 应用
    ↓
发送任务到 Celery
    ↓
Redis/RabbitMQ (消息队列)
    ↓
Celery Worker 1, 2, 3... (执行任务)
```

#### 代码示例

```python
from celery import Celery

celery_app = Celery(
    'tasks',
    broker='redis://localhost:6379/0',
    backend='redis://localhost:6379/0'
)

@celery_app.task
def daily_task():
    # 任务逻辑
    pass

# 使用 Celery Beat 定时执行
from celery.schedules import crontab

celery_app.conf.beat_schedule = {
    'daily-task': {
        'task': 'daily_task',
        'schedule': crontab(hour=2, minute=0),
    },
}
```

### 3. Dramatiq ⭐⭐⭐⭐ (高性能推荐)

#### 特点

**优点：**
- ✅ **高性能**：比 Celery 性能更好
- ✅ **简单易用**：API 设计更简洁
- ✅ **分布式**：支持多 Worker
- ✅ **现代化**：使用 Python 3.7+ 新特性
- ✅ **类型支持**：原生支持类型提示

**缺点：**
- ❌ 需要 Redis/RabbitMQ
- ❌ 生态不如 Celery 丰富
- ❌ 文档和社区相对较小

#### 适用场景

- ✅ 需要高性能任务队列
- ✅ 现代 Python 项目（3.7+）
- ✅ 中型应用
- ✅ 不想用 Celery 的复杂性

#### 代码示例

```python
import dramatiq
from dramatiq.brokers.redis import RedisBroker

redis_broker = RedisBroker(host="localhost", port=6379, db=0)
dramatiq.set_broker(redis_broker)

@dramatiq.actor
def daily_task():
    # 任务逻辑
    pass

# 使用 dramatiq-cron 定时执行
from dramatiq_cron import cron

@cron("0 2 * * *")  # 每天凌晨2点
@dramatiq.actor
def scheduled_task():
    daily_task.send()
```

### 4. FastAPI BackgroundTasks ⭐⭐⭐ (轻量级)

#### 特点

**优点：**
- ✅ **零依赖**：FastAPI 内置，无需安装
- ✅ **极简**：使用最简单
- ✅ **无缝集成**：与 FastAPI 完美集成

**缺点：**
- ❌ **不支持定时**：只能延迟执行，不能定时重复
- ❌ **不能持久化**：服务重启任务丢失
- ❌ **同步执行**：默认同步，可能阻塞请求

#### 适用场景

- ✅ 请求后需要执行的轻量级后台任务
- ✅ 发送邮件、清理临时文件等
- ✅ 不需要定时重复执行
- ❌ **不适合定时任务场景**

#### 代码示例

```python
from fastapi import BackgroundTasks

@router.post("/send-email")
async def send_email(
    background_tasks: BackgroundTasks,
    email: str
):
    background_tasks.add_task(send_email_task, email)
    return {"message": "邮件发送中"}
```

### 5. RQ (Redis Queue) ⭐⭐⭐ (简单队列)

#### 特点

**优点：**
- ✅ **简单易用**：比 Celery 简单
- ✅ **轻量级**：代码量小
- ✅ **Redis 后端**：使用 Redis 作为队列

**缺点：**
- ❌ 功能相对简单
- ❌ 不支持复杂的任务调度
- ❌ 需要 Redis

#### 适用场景

- ✅ 简单任务队列
- ✅ 已有 Redis 环境
- ✅ 不需要复杂调度功能

## 推荐方案

### 🎯 基于你的项目情况，推荐：**APScheduler**

#### 推荐理由

1. **项目现状**
   - ✅ FastAPI 应用（单机部署）
   - ✅ PostgreSQL 数据库（可用于持久化）
   - ✅ 没有额外的消息队列（Redis/RabbitMQ）
   - ✅ 任务场景相对简单

2. **APScheduler 优势**
   - ✅ **零额外服务**：不需要安装 Redis/RabbitMQ
   - ✅ **快速集成**：几行代码即可集成到 FastAPI
   - ✅ **功能足够**：支持 Cron、间隔等常用场景
   - ✅ **易于管理**：可以通过 FastAPI API 动态管理任务
   - ✅ **可选持久化**：可以使用 PostgreSQL 持久化任务（项目已有）

3. **适用场景示例**
   ```python
   # 每天凌晨2点同步数据
   scheduler.add_job(sync_data, CronTrigger(hour=2, minute=0))
   
   # 每5分钟检查状态
   scheduler.add_job(check_status, 'interval', minutes=5)
   
   # 每小时生成报表
   scheduler.add_job(generate_report, CronTrigger(minute=0))
   ```

## 快速开始指南

### 方案一：APScheduler（推荐）

#### 1. 安装依赖

```bash
cd E:\finance\api\backend
uv add apscheduler
```

#### 2. 创建定时任务模块

**目录结构：**
```
app/
├── scheduler/
│   ├── __init__.py
│   ├── scheduler.py        # 调度器配置
│   └── jobs/
│       ├── __init__.py
│       └── example_job.py  # 任务示例
```

#### 3. 基础实现

**`app/scheduler/scheduler.py`：**
```python
from apscheduler.schedulers.asyncio import AsyncIOScheduler
from apscheduler.jobstores.memory import MemoryJobStore
from apscheduler.triggers.cron import CronTrigger
import logging

logger = logging.getLogger(__name__)

scheduler = AsyncIOScheduler(
    jobstores={'default': MemoryJobStore()},
    timezone='Asia/Shanghai'
)

def init_scheduler(app):
    @app.on_event("startup")
    async def startup_event():
        scheduler.start()
        logger.info("定时任务调度器已启动")
        register_jobs()
    
    @app.on_event("shutdown")
    async def shutdown_event():
        scheduler.shutdown()
        logger.info("定时任务调度器已关闭")

def register_jobs():
    from app.scheduler.jobs import example_job
    
    # 注册任务
    scheduler.add_job(
        example_job.daily_task,
        CronTrigger(hour=2, minute=0),
        id='daily_task',
        name='每日任务',
        replace_existing=True
    )
```

**`app/scheduler/jobs/example_job.py`：**
```python
import logging
from datetime import datetime

logger = logging.getLogger(__name__)

async def daily_task():
    logger.info(f"执行每日任务 - {datetime.now()}")
    # 你的业务逻辑
    pass
```

**`app/main.py`：**
```python
from app.scheduler import init_scheduler

app = FastAPI(...)

# 初始化调度器
init_scheduler(app)
```

### 方案二：如果需要持久化（使用 PostgreSQL）

如果希望任务在服务重启后仍然保留，可以使用数据库持久化：

```python
from apscheduler.jobstores.sqlalchemy import SQLAlchemyJobStore
from app.core.db import engine

scheduler = AsyncIOScheduler(
    jobstores={
        'default': SQLAlchemyJobStore(
            engine=engine,
            tablename='apscheduler_jobs'
        )
    },
    timezone='Asia/Shanghai'
)
```

---

### 方案三：如果未来需要分布式（迁移到 Celery）

如果未来应用规模扩大，需要分布式任务执行，可以平滑迁移到 Celery：

1. **先使用 APScheduler**，满足当前需求
2. **预留接口抽象**，方便后续替换
3. **需要时迁移**：当需要分布式或多服务器时，再引入 Celery

## 决策流程图

```
开始
  ↓
是否需要分布式执行？
  ├─ 否 → 使用 APScheduler ✅
  └─ 是 → 是否需要高性能？
      ├─ 是 → 使用 Dramatiq
      └─ 否 → 使用 Celery

是否需要持久化？
  ├─ 否 → 使用 MemoryJobStore
  └─ 是 → 使用 SQLAlchemyJobStore (PostgreSQL)

任务数量？
  ├─ < 100 → APScheduler 足够
  ├─ 100-1000 → 考虑 Celery/Dramatiq
  └─ > 1000 → 必须使用 Celery/Dramatiq
```

## 总结

### 推荐方案

**当前阶段：APScheduler**

- ✅ 简单、快速、零依赖
- ✅ 满足大多数定时任务需求
- ✅ 易于集成和管理
- ✅ 可选持久化（使用现有 PostgreSQL）

### 未来扩展

如果未来需要：
- **分布式执行** → 迁移到 Celery/Dramatiq
- **任务队列** → 引入 Celery
- **高性能场景** → 考虑 Dramatiq
